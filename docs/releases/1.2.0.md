# JukeboxCli 1.2.0

Fullscreen MilkDrop on Mac and Linux, with proper presets from the first frame.
No M/headphones intro. Same player, queue and release on both platforms.

## Mac

- Optional projectM 4 companion for macOS 14.4 or newer.
- One opt-in install includes 9,795 Cream of the Crop presets and MilkDrop textures.
- Captures only JukeboxCli's existing mpv audio. No virtual driver, microphone
  recording or second stream. macOS may ask for audio-recording permission.
- `F` in Now Playing opens effects. `N`/Space changes preset; Esc/Q closes them.

After updating, install the optional pack from Settings → Player appearance or:

```sh
jukeboxcli --install-visualizer
```

Apple Command Line Tools are required. The installer adds CMake through Homebrew
if needed, verifies its downloads and builds the companion locally.

## Linux

- Optional Cream of the Crop presets with textures, plus Classic/Cream/Combined
  selection under Settings → Player appearance → MilkDrop packs.
- A private Qt/PulseAudio frontend selects a real preset before drawing. No
  timed shortcut, compositor-specific helper or visible branding screen.
- The Arch installer handles missing core tools and projectM/Classic dependencies.
  Extra packs stay opt-in. `--no-visualizer` keeps the core player only;
  `--no-system-deps` leaves system packages to you.

Existing Linux installs can rebuild the companion with
`jukeboxcli --install-linux-visualizer`. It requires libprojectM 3.1.12, Qt 5
and the build tools described in the Linux guide. Audio capture still uses the
active system-output monitor, so other apps can affect its visuals.

## Update

```sh
brew update
brew upgrade jukeboxcli
jukeboxcli --version
```

For source installs, run `./update.sh` from your checkout. The version should be
`1.2.0`. Music and settings are preserved. Normal startup never downloads extra
preset packs; ordinary playback and terminal visuals work without fullscreen.

Build, packaging, playback-lifetime and UI tests cover both platforms. Community
presets vary in GPU cost and rendering compatibility. Mac testing over screen
sharing showed some remote-display artefacts; longer direct-display testing is
still useful. Intel Macs are not part of automated install checks.
