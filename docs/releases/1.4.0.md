# JukeboxCli 1.4.0

Portable playlists, genre browsing and useful diagnostics, with a few optional
ways to make the player feel more like yours. One release for Mac and Linux.

## What's new

- **Portable playlists:** open Playlists (`2`), then `I` to import or `E` to
  export JSON or extended M3U. Preview before adding tracks to the queue. Local
  files use music-folder-relative paths; missing files are skipped. No automatic
  playback, downloads or overwriting existing exports.
- **Genres:** Library `B` now cycles songs, artists, albums and genres. Settings
  → Scan genre tags reads existing files without changing them. New downloads
  retain genre metadata when the source supplies it.
- **Session diagnostics:** Settings → Session diagnostics shows recent errors
  and download timing/pacing. `R` refreshes; `E` exports a sanitised report.
  Nothing is uploaded automatically. Review reports before sharing them.
- **Artwork colours:** an opt-in player accent drawn from the cover. Enable it
  in Settings → Player appearance; missing artwork keeps the selected theme.
- **Keyboard and mouse:** opt-in `j`/`k` navigation and mouse row selection in
  Settings → Keyboard and mouse. Text entry is unchanged; clicks don't play or
  delete tracks. Existing controls and wheel scrolling remain the default.
- **Discover pagination:** optionally load more results near the end of the
  list. This expands search results, not the playback queue. Manual `L` remains.

Playlist imports need matching relative folders on the receiving machine.
Exported stream URLs can contain private query tokens: review before sharing.
See the [feature guide](../library-and-diagnostics.md) for controls and limits.

## Update

```sh
brew update
brew upgrade jukeboxcli
jukeboxcli --version
```

Expect `1.4.0`. Quit and reopen after upgrading. Source installs can run
`./update.sh` from their checkout. Existing music, settings and visualiser packs
are kept; the new appearance and navigation options are off unless you enable them.

Physical media keys, terminal rendering and long MilkDrop sessions still benefit
from hands-on testing. Automated checks do not cover every terminal or device.
