# JukeboxCli 1.8.2

Cookies are optional. This patch makes anonymous mode explicit and stops generic
YouTube failures from looking like a missing app setting. Mac and Linux share
the same release.

## What changed

- Settings labels a missing cookie profile **Anonymous · cookies optional**.
  **Keep anonymous playback** returns without writing preferences.
- Playback and pasted YouTube metadata distinguish source verification, rate
  limits, restricted items, JavaScript solver failures and source refusal.
  Messages don't expose signed URLs or browser paths.
- A cookie-read error is shown only if the request actually used cookies.
  Configured browser/file choices and explicit one-item Retry without cookies
  keep their previous behaviour. No browser is read or selected automatically.

Public YouTube playback already tried anonymous access in 1.8.1. This is a status
and error-reporting correction, not a new login backend or a way to bypass source
verification. A connection can still be challenged and a video can still require
authentication. Cookies may help, but neither cookies nor this patch guarantee
access to every item/network. Update yt-dlp when extraction changes.

## Checks

960 tests passed with 6 skipped on Apple Silicon macOS, plus typecheck.
Real cookie-free YouTube video/audio/video acceptance passed on Apple Silicon:
decoded sound, one mpv, preserved queue/position and owned-process cleanup.
Playback was muted, with an isolated profile and no actual browser access.
Regression tests cover no-profile audio/video, optional settings and safe source
failure classification. Mac/Linux installation checks gate stable publication.

## Update

```sh
brew update
brew upgrade jukeboxcli
jukeboxcli --version
```

Expect **1.8.2**, then quit/reopen. Music, queues, optional packs and preferences
are kept. Source installs can use `./update.sh`.
